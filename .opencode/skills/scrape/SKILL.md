# Scrape Skill — documenting the 42 Intra API surface

## Purpose

Maintain `endpoints.md` (repo root) as the single source of truth for every HTTP
interaction in `42_cli`. The file must be deterministic, re-runnable and safe to
read from C++ code.

## Procedure

### 1. Inventory

Extract every URL the code touches (they live mostly in `src/network.cpp`):

```bash
grep -oE 'https?://[^"'"'"']+' src/network.cpp | sort -u
```

Hosts to recognize:
- `profile.intra.42.fr` — profile pages, slots, users, JSON endpoints
- `auth.42.fr` — login / sign-in / CSRF token dance
- `projects.intra.42.fr` — project pages, project_data.json, feedbacks, scale_teams
- `meta.intra.42.fr` — clusters.json
- `cdn.intra.42.fr` — avatar/profile images
- `intra.42.fr` — generic entry points, referer

### 2. Map each endpoint to its consumer

For each URL, find the `network::` function that calls it (`src/network.hpp`) and
the struct that holds its data (`include/types.hpp`). Table:

| Host | Path | Method | Auth/Headers | Params | Response | Consumer |
|------|------|--------|--------------|--------|----------|----------|
| profile.intra.42.fr | /users/<login> | GET | Accept: application/json (cookie) | login path | Profile JSON | `network::fetch_user_profile` |

Auth conventions to capture:
- Session cookie file path (`cookie_file_path()`, `$XDG_CACHE_HOME`/`~/.cache`)
- `Referer` header (e.g. `https://profile.intra.42.fr/slots`)
- `Origin` header for POSTs (e.g. `https://profile.intra.42.fr/slots`)
- Login flow needs CSRF token from the sign-in form at `auth.42.fr`
- v3 early-access switch endpoints on `profile.intra.42.fr`

### 3. Verify live (when possible)

Use a real cookie if one exists on disk. Prefer JSON/curl to keep output small:

```bash
curl -s -b ~/.local/share/intra_cli/cookies.txt \
     -H 'Accept: application/json' \
     https://profile.intra.42.fr/users/<login>
```

If the login flow cannot be replayed, capture the *expected* request/response
from the page's HTML/JS and mark the row `[unverified]`.

### 4. Public API vs scraper endpoints

Distinguish two tiers in `endpoints.md`:
- **Verifiable public JSON** (slots.json, clusters.json, project_data.json,
  users/<login> with JSON accept) — solid, direct bash/curl-able.
- **HTML-scrape endpoints** (profile HTML, feedbacks/scale_teams pages) — mark
  the exact HTML node/attribute the parser reads (`html_parser.cpp`) so a change
  on the site is easy to diff.

### 5. Write `endpoints.md`

Standard layout:

```markdown
# 42 Intra endpoints
Generated by the scrape skill. Refresh with: `opencode/scraper` (or manually per
the scrape skill).

## Auth model
...

## Endpoints
| # | Host | Path | Method | Auth/Headers | Body/Query | Response | Consumer |
...

## Details
### <N> GET profile.intra.42.fr/users/<login>
...
```

Rules:
- One row per endpoint; deduplicate by host+path.
- Never embed secrets/cookie contents — paths and header *names* only.
- Tag anything not live-verified `[unverified]`.
- Keep it diff-friendly: stable ordering (host, then path).

## Completion criteria

- [ ] Every URL from the code grep is represented.
- [ ] Every item maps to a `network::` consumer.
- [ ] Auth/header/params captured; unspecified = "none".
- [ ] Html-scrape rows note the parsed node.
- [ ] `endpoints.md` written in the standard layout, no secrets.
